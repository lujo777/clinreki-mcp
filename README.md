# clinreki-mcp

MCP-сервер для **клинических рекомендаций Минздрава РФ** (рубрикатор
[cr.minzdrav.gov.ru](https://cr.minzdrav.gov.ru)). Оборачивает открытый API
`apicr.minzdrav.gov.ru` в набор инструментов для языковых моделей: поиск с
фильтрами, метаданные документов и — главное — **полный текст разделов в виде
читаемого Markdown** (таблицы → GFM, картинки выносятся отдельно).

> Неофициальный проект. Не связан с Минздравом РФ. Данные принадлежат
> правообладателям; содержимое рекомендаций не является медицинской консультацией.

## Возможности

- Поиск КР по названию, **коду МКБ-10** (например `H50.0`), возрасту,
  специальности, разработчику; с пагинацией и сортировкой.
- Метаданные КР + оглавление разделов (без выгрузки многомегабайтного текста).
- Раздел или весь документ как **Markdown** с постраничной выдачей.
- **Картинки** (встроены как base64) не раздувают контекст: в тексте — компактный
  плейсхолдер, а само изображение отдаётся отдельным инструментом (его «видит» модель).
- Поиск и навигация по справочнику МКБ-10 без выгрузки всех 12 794 узлов.
- Справочники разработчиков (НКО) и специальностей.

## Установка

Нужен [uv](https://docs.astral.sh/uv/) и Python ≥ 3.11.

```bash
uv sync                 # установить зависимости
uv run clinreki-mcp     # запустить сервер (транспорт stdio)
```

## Инструменты

| Инструмент | Назначение |
|---|---|
| `search_clinrecs(name, mkb_code, age_category, specialty, nko_id, status, sort_field, sort_desc, page, page_size)` | Поиск/список КР. `id` в результатах = `CodeVersion` для остальных инструментов. По умолчанию возвращаются **все** записи (фильтр `status` не применяется). Фильтр по специальности — клиентский, покрытие частичное. |
| `get_clinrec(code_version, include_toc=True)` | Метаданные КР + оглавление разделов. Полный текст не возвращается. |
| `get_clinrec_section(code_version, section_id\|section_title\|index, output_format, max_chars, offset)` | Один раздел как Markdown (`output_format`: `markdown`/`text`/`html`). Большие разделы — кусками (`next_offset`). Картинки — в `images[]`. |
| `get_clinrec_markdown(code_version, max_chars, offset)` | Весь документ одним Markdown с пагинацией. |
| `get_clinrec_image(code_version, image_index, section_id, save_path)` | Картинка как изображение (модель её видит) либо сохранение в файл. |
| `search_mkb(query, limit)` | Поиск по МКБ-10 (префикс кода / подстрока названия). |
| `get_mkb_children(node_id)` | Навигация по дереву МКБ-10. |
| `list_developers(query, limit)` | Список разработчиков (НКО). |
| `list_specialties()` | Справочник специальностей (агрегирован из записей). |

### Типовой сценарий

1. `search_clinrecs(name="косоглазие")` → берём `id` (например `"922_1"`).
2. `get_clinrec("922_1")` → метаданные и оглавление (`toc`).
3. `get_clinrec_section("922_1", section_id="doc_diag_2_4")` → раздел в Markdown.
4. `get_clinrec_image("922_1", image_index=0, section_id="doc_b")` → схема/рисунок.

## Подключение к Claude Desktop

```bash
uv run mcp install src/clinreki_mcp/server.py --name "Клинреки"
```

либо вручную в `claude_desktop_config.json`:

```json
{
  "mcpServers": {
    "clinreki": {
      "command": "uv",
      "args": ["run", "clinreki-mcp"],
      "cwd": "/полный/путь/к/clinreki-mcp"
    }
  }
}
```

Отладка инструментов через инспектор:

```bash
uv run mcp dev src/clinreki_mcp/server.py
```

## Заметки об API

- Единый endpoint `https://apicr.minzdrav.gov.ru/api.ashx`, операция — параметр `?op=`.
  Без авторизации и CORS-ограничений.
- В ответе поиска ключ ошибок реально называется **`Erorrs`** (опечатка в API) — обрабатывается.
- Текст документа лежит в `obj.sections[]` (поле `textBlock` пустое). Раздел адресуется
  стабильным `id` (`doc_diag_2_4`, `doc_criteria`, `doc_b`, …).
- `status` — рабочий статус записи (без фильтра — 1798, `status=0` — 721, `status=1` — 185);
  по умолчанию не фильтруем.
- Картинки встроены как `data:image/png;base64,…`; справочник МКБ — ~3.2 МБ. Справочники
  кэшируются в памяти на время жизни процесса.
- Серверного фильтра по специальности нет — он реализован на стороне клиента.
